ПРАКТИЧЕСКИЙ SDK ПОДКЛЮЧАЕМЫХ ВОЗМОЖНОСТЕЙ

Корень локального хранилища указан в capabilities.storage_root. Все пути
единиц строятся от него, а не от расположения Python-пакета Jarvis.
Actions/handlers/modules в этом хранилище — пользовательские расширения.
Системные actions уже реализованы ядром; не создавай их файловые копии.

Файловые инструменты module_manager:
read_file(path, start_line, end_line): UTF-8 с 1-based номерами строк;
неиспользуемые границы передаются null. write_file(path, content) заменяет
весь файл и создаёт родителей. edit_file заменяет диапазон включительно.
execute_command(command, cwd) выполняет bash до завершения без timeout.
cwd=null означает рабочий каталог проекта; абсолютные пути разрешены.
ls/find/rg/mkdir/rm/mv/git/тесты выполняются через execute_command.
Не создавай отдельные actions для этих shell-операций.

ОДИН КАТАЛОГ — ОДНА ЕДИНИЦА
actions/<id>/action.py: run(data, context) и create_action().
handlers/<id>/handler.py: start(context) и create_handler().
modules/<id>/module.py: create_module(); действия/handlers в подкаталогах
actions/<unit>/action.py и handlers/<unit>/handler.py.
Имя каталога определяет ID. Не передавай id фабрикам и не устанавливай его
в определении. Корневые имена: латинская буква, затем буквы/цифры/_/-.
Точки разрешены только в назначаемом ядром ID части модуля: module.unit.
Модуль включается и приостанавливается целиком.

СХЕМЫ
from jarvis.core.protocol import object_schema
object_schema({"text": {"type": "string"}}) создаёт строгую объектную схему.
Все поля обязательны, additionalProperties=false. Опциональное значение
выражается как {"type": ["string", "null"]} и передаётся явно как null.
У array обязателен items, у вложенных объектов — такие же строгие схемы.
Аргументы и результат action являются объектами. Прикладной отказ нужно
описать собственным result_schema; ядро не навязывает универсальное error.

ПОЛНЫЙ ПРИМЕР ACTION
from jarvis.capabilities import action_definition
from jarvis.core.protocol import object_schema

def run(data, context):
    return {"text": data["text"]}

def create_action():
    return action_definition(
        "Return the supplied text.",
        object_schema({"text": {"type": "string"}}),
        object_schema({"text": {"type": "string"}}),
        run,
    )

Возвращается только data результата; type=call_result и call_id добавляет
runtime. Не создавай envelope самостоятельно и не публикуй events из action.
Если результат отложен: from jarvis.capabilities import PENDING;
верни PENDING и позже ровно один раз вызови context.complete(result_dict).
Не совмещай complete с обычным return результата. Непредвиденное исключение
становится capability_error вызывающему агенту. Таймаута результата нет.

МУЛЬТИМОДАЛЬНЫЙ РЕЗУЛЬТАТ
from jarvis.capabilities import input_part, PENDING
part = input_part("file", "application/pdf", base64_data, name="report.pdf")
context.complete(result_dict, parts=(part,))
return PENDING
type части: image/audio/video/file; data — base64 без data-url.
Сохраняй meaningful name: оно проходит через worker, core и память.
Каждый InputPart относится к тому же call_result; base64 не кладётся в data.

ПОЛНЫЙ ПРИМЕР HANDLER
from jarvis.capabilities import event_definition, handler_definition
from jarvis.core.protocol import object_schema

NOTICE = event_definition("notice", "External notification.",
                          object_schema({"text": {"type": "string"}}))

def start(context):
    # Реальная реализация ожидает внешние данные и вызывает:
    # context.emit(NOTICE, {"text": "new data"})
    context.stop_event.wait()

def create_handler():
    return handler_definition("Observe an external source.", NOTICE, start)

Один handler объявляет одно событие. start может блокироваться: runtime
выполняет каждый handler в своём execution context. Реагируй на stop_event;
закрывай сеть/файлы/устройства при остановке. context.emit(..., target=None)
рассылает событие агентам с назначенным и включённым handler/module;
target=agent_id адресует его. Не используй результат action как handler event.

ПОЛНЫЙ ПРИМЕР MODULE
from jarvis.capabilities import module_definition
from .actions.echo.action import create_action
from .handlers.notice.handler import create_handler

def create_module():
    return module_definition("Example external integration.",
                             (create_action(),), (create_handler(),))

Фабрики actions/handlers должны находиться в их собственных файлах; loader
сверяет источник каждой декларации и полное покрытие unit-каталогов.
Общий код модуля может импортироваться относительными импортами. В module.py
нельзя выполнять actions или запускать фоновые observers при импорте.

ОКРУЖЕНИЕ И LIFECYCLE
Простому расширению отдельная .venv и .env не обязательны. Если нужны
зависимости, requirements.txt лежит рядом с entrypoint; закрепи версии.
Создай .venv в каталоге единицы и установи зависимости execute_command.
SDK Jarvis доступен worker через штатное окружение, core site-packages не меняй.
Если нужен .env, расширение само его читает. Ядро не загружает его специально.
При необходимости фабрики принимают prepare(config) и teardown(config).
prepare вызывается только при старте runtime, teardown — при выгрузке.
config.jarvis_dir/config.unit_dir/config.project_root дают нужные пути.
describe разрешает импорт кода, но не запускает hooks/handlers/actions.
Каждый invocation action исполняется независимо в процессе. Обычные Python
globals не разделяются между invocation-процессами; для общего состояния
используй подходящий IPC или хранилище самого расширения.

КОНТЕКСТ ACTION
context.agent_id — caller; context.call_id — уникальный вызов;
context.action_id — имя действия; context.module_id — контейнер либо None.
context.config.jarvis_dir — storage root, context.config.unit_dir — каталог
единицы; context.metadata содержит preset/agent_name. context.complete
завершает вызов. Сервисы core доступны через существующие RPC-прокси
context.agent_manager и context.capabilities; не импортируй живой runtime.

ПРОВЕРКА И ПОДКЛЮЧЕНИЕ
capability_info(kind,id) получает полное описание и схемы без старта runtime.
Проверь синтаксис python -m compileall и поведение тестами/прямым вызовом
функций в отдельном процессе. Не выполняй GUI/деструктивные действия ради
проверки без разрешения родителя. Не утверждай успех по одному импорту.
list_capabilities даёт обзор диска/runtime/global state. toggle_capability
переключает running/paused, но не назначения. enable_capability у родителя
назначает ему готовую единицу. Known/local disabled/global paused/runtime
loaded — разные состояния; disabled единица остаётся известной модели.
