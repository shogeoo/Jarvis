# Jarvis

Личный цифровой ассистент Georgiy Shonichev. Ядро находится в разработке.

`.env` содержит только `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` и
необязательный `LLM_REASONING_EFFORT` (пусто — дефолт провайдера).
Остальные настройки заданы в коде. Хранилище — `.jarvis` в корне проекта.
Все модели речи находятся в `.jarvis/runtime/models/`.
STT и TTS настроены на CUDA без CPU fallback; VAD работает на CPU.
Для TTS используется установленный бинарник `s2`.

Запуск: `python -m jarvis`.
Тесты: `python -m unittest discover -s tests`.

Systemprompt собирается в порядке: `personprompt`, общий неизменяемый
`masterprompt`, одна строка поддерживаемых модальностей, `CAPABILITY`.
Названия разделов не выводятся; между блоками — одна пустая строка.
Документация разработки находится только в личности module_manager,
не в общем masterprompt.

`CAPABILITY` — английский JSON-каталог с массивами `actions`, `events`,
`modules`. В нём только включённые у данного агента возможности. Каждый модуль
содержит свои полные `actions` и `events`, без повторения в корневых массивах.
Новые включённые элементы добавляются в конец; порядок сохраняется при restore.
Описание наблюдателя не передаётся модели: она получает описание его события.

Любое событие: `{"event_id":"event_name","data":{}}`.
Ответ модели: `{"actions":[{"action_id":"action_name","call_id":"unique_call","data":{}}]}`.
Результат: `{"event_id":"call_result","call_id":"unique_call","data":{}}`.
`call_id` уникален за весь контекст агента. Действия выполняются независимо,
без таймаута результата; один вызов имеет максимум один финальный результат.

Входные параметры описаны через `type`, `properties`, `required` и `default`.
Необязательные параметры можно опускать: runtime подставит их defaults.
Описание результата содержит только `properties` с описаниями возможных полей;
результат может содержать их подмножество. Исходные данные и история не удаляются
ради перехода сохранённых событий на новый envelope.
