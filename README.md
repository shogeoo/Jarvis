# Jarvis

Jarvis — модульная event-thinking-action система. Модель получает события в
строгом JSON, отвечает массивом actions в строгом JSON и не использует tool
calling. Каждый агент имеет собственные контекст, очередь, поток и пресет.

Текущее ядро не реализует долговременную память и автозапуск вместе с ОС.

## Структура проекта

```text
jarvis/
  application.py              # сборка всех частей при запуске
  cli.py                      # жизненный цикл процесса
  core/                       # неизменяемое ядро
    protocol.py               # Event, ActionRequest и JSON Schema
    runtime.py                # агенты, пачки, модельный цикл, EventBus
    registry.py               # реестры actions и events
    prompts.py                # сборка systemprompt в памяти
    lifecycle.py              # процессы и пул исполнения
  modules/                    # Python API и загрузчик модулей
    api.py
    manager.py
  presets/                    # чтение файловых пресетов
    store.py
  infrastructure/             # конфигурация, диагностика, модельный API

.jarvis/
  environment.txt             # общее техническое описание среды
  modules/                    # изменяемые способности Jarvis
  presets/                    # постоянные конфигурации агентов
  runtime/                    # временные данные, не попадают в Git
```

`jarvis/core` знает только общий протокол. Telegram, речь, работа с файлами,
создание агентов и другие способности реализуются каталогами в
`.jarvis/modules`.

## Установка и запуск

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[cuda]'
cp .env.example .env
.venv/bin/jarvis
```

Для распознавания на CPU используется `.venv/bin/pip install -e '.[speech]'` и
`STT_DEVICE=cpu`. Установка без extra содержит только ядро; тогда речевые
модули нужно отключить или убрать из пресета. Микрофон использует `parec`,
воспроизведение речи — `ffplay`.

Основные переменные находятся в `.env.example`: параметры LLM, STT и TTS.
`JARVIS_DIR` по умолчанию указывает на `.jarvis` в корне проекта.

Модели речи можно заранее скачать скриптом самого модуля:

```bash
./.jarvis/modules/speech_input/download_models.sh
```

## Протокол

Событие и действие имеют одинаковую оболочку:

```json
{
  "type": "module.name",
  "data": {}
}
```

Одно событие занимает одно сообщение API с ролью `user`. Модель отвечает:

```json
{
  "actions": [
    {"type": "speech_output.speak", "data": {"text": "Добрый вечер."}}
  ]
}
```

Actions выполняются последовательно. Ошибка одного action не отменяет
следующие. Ядро не создаёт универсальный `action_result`: модуль сам объявляет
и публикует событие результата. Если модуль не отправил событие, агент не
получит обратной связи и его цепочка остановится до нового внешнего события.

`no_action` встроен в ядро и разрешён только как единственный action ответа.
Сочетание с другими actions считается ошибкой структуры.

## Пачки событий

Пока агент обращается к модели или выполняет весь массив actions, он занят.
Новые события накапливаются в пачке. После завершения цикла пачка добавляется в
контекст как последовательность отдельных сообщений в точном порядке
возникновения событий.

При неправильном JSON исходный ответ сохраняется в контексте, а следующим
сообщением добавляется `structure_error`. Агент остаётся занят и показывает
модели только эту ошибку. Остальная пачка ждёт корректного ответа и завершения
его actions.

## Модули

Каждый модуль имеет структуру:

```text
.jarvis/modules/telegram/
  module.json
  module.py
  actions/
  handlers/
```

`module.py` возвращает `jarvis.modules.Module`. Все имена actions и events
начинаются с `module_id.`. Схемы объектов строгие: перечисляют все обязательные
поля и запрещают дополнительные.

Handler запускается сразу после запуска Jarvis. Его неадресное событие получают
все активные агенты, у которых этот модуль указан в пресете. Событие из action
по умолчанию адресуется только вызвавшему агенту.

Стандартные модули:

- `agents` — экземпляры агентов, сообщения и пресеты;
- `module_manager` — создание, тестирование, применение и назначение модулей;
- `speech_input` — микрофон, VAD и faster-whisper;
- `speech_output` — Fish Audio и воспроизведение;
- `system` — штатное завершение Jarvis.

## Пресеты

Пресет хранится отдельным каталогом:

```text
.jarvis/presets/developer/
  personprompt.txt
  modules.json
  preset.json                 # необязательный флаг protected
```

`modules.json` содержит массив `module_id`. Весь модуль целиком доступен агенту.
Полный systemprompt на диске не хранится. Перед каждым новым циклом он собирается
в памяти из:

1. `personprompt.txt` пресета;
2. `.jarvis/environment.txt`;
3. модальностей текущей модели;
4. актуального каталога actions и events подключённых модулей.

Поэтому обновление модуля применяется к уже работающим агентам на следующей
границе цикла, а накопленный контекст сохраняется.

`main` — обычный первый экземпляр с пресетом `main` и случайным ID вида
`agent-007`. Его пресет помечен `protected`, поэтому его нельзя создать заново
или удалить; в его
`modules.json` разрешено только добавлять модули. `module_manager` автоматически
не создаётся: `main` запускает его через `agents.spawn`, когда это требуется.
