# Jarvis

Личный цифровой ассистент Georgiy Shonichev. Ядро находится в разработке.

Параметры API в `.env`: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_API_MODEL` и
необязательный `LLM_REASONING_EFFORT` (пусто — дефолт провайдера).
Для режима подписки задай `CHATGPT_SUBSCRIPTION_ENABLED=true`,
`LLM_SUBSCRIPTION_MODEL` и `LLM_API_MODEL`: первая модель работает через вход
ChatGPT OAuth, вторая — через API при исчерпании лимита. Прежний `LLM_MODEL`
пока принимается как имя API-модели. При первом запуске вход ChatGPT
откроется в браузере до события `system_started`.
Подписка использует собственный цикл Jarvis и прямой Responses-транспорт
с ChatGPT OAuth; Codex как агентный runtime не запускается. Входные модальности
подписки: `text` и `image`. Остальные вложения сохраняются в памяти Jarvis,
но не передаются подписному маршруту нативно. Если лимит подписки достигнут,
тот же запрос передаётся настроенному API с его моделью и модальностями.
Состояние входа Jarvis хранится в `.jarvis/runtime/auth/chatgpt.json`, отдельно
от Codex CLI и вне Git.
Для такого переключения API-ключ и модель должны быть настроены заранее.
Остальные настройки заданы в коде. Хранилище — `.jarvis` в корне проекта.
Все модели речи находятся в `.jarvis/runtime/models/`.
STT и TTS настроены на CUDA без CPU fallback; VAD работает на CPU.
Для TTS используется установленный бинарник `s2`.

Запуск: `python -m jarvis`.
Тесты: `python -m unittest discover -s tests`.

Одно сообщение `system` собирается из разделов `ENVIRONMENT:` (общий
неизменяемый masterprompt), `PERSON:` (личность preset), `MEMORY:`
(семантическая память только для Jarvis), `MODEL INFO:` (точный ID текущей
модели и модальности) и `CAPABILITIES:` (динамический каталог). Заголовок
стоит непосредственно над содержимым; между разделами одна пустая строка.
Документация разработки находится только в личности module_manager,
не в общем masterprompt.

`MEMORY` содержит подтверждённые устойчивые факты и сохраняется в
`.jarvis/memory/main/semantic.json` как `{"entries":[{"id":"mem_000001","content":"..."}]}`.
Системные действия `memory_write(content)`, `memory_edit(id, content)` и
`memory_delete(id)` доступны только Jarvis. Следующий inference получает
актуальный снимок памяти после изменений.

Экземпляры сохраняются в `.jarvis/memory/<preset>/<agent_id>/`; для main
каталог — `.jarvis/memory/main/`. Каждый содержит `instance.json` с настройками
экземпляра, `context.json` с массивом сообщений и `files/` с бинарными частями.
В сохранённом сообщении бинарник заменён на `file_id`, например
`{"type":"image_url","image_url":{"file_id":"file_000001"}}`; на диске он
лежит в `files/file_000001.jpg`. ID файлов уникальны для всего Jarvis, имена
исходных вложений в ссылке не сохраняются. У main зарезервированы каталоги
`long_term/sessions/` и `long_term/files/` для будущей функциональности.
Все JSON-файлы в `.jarvis` записываются с форматированием.
Сохранение `instance.json` и `context.json` использует временный журнал отката;
после успешной записи он удаляется, постоянных каталогов версий нет.

`CAPABILITIES` — английский JSON-каталог с массивами `actions`, `events`,
`modules`. В нём только включённые у данного агента возможности. Каждый модуль
содержит свои полные `actions` и `events`, без повторения в корневых массивах.
Новые включённые элементы добавляются в конец; порядок сохраняется при restore.
Описание наблюдателя не передаётся модели: она получает описание его события.

Любое событие: `{"event_id":"event_name","data":{}}`.
Ответ модели: `{"actions":[{"action_id":"action_name","call_id":"unique_call","data":{}}]}`.
Результат: `{"event_id":"call_result","call_id":"unique_call","data":{}}`.
`call_id` уникален за весь контекст агента. Действия выполняются независимо,
без таймаута результата; один вызов имеет максимум один финальный результат.

Входные параметры описаны через `type`, `properties`, `required` и `default`.
Необязательные параметры можно опускать: runtime подставит их defaults.
Описание результата содержит только `properties` с описаниями возможных полей;
результат может содержать их подмножество. Исходные данные и история не удаляются
ради перехода сохранённых событий на новый envelope.
