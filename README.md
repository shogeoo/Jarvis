# Jarvis — голосовой ассистент

Локальное распознавание речи (русский/английский) с нарезкой на аудио-чанки
по паузам. Микрофон → VAD → WAV-сегменты → faster-whisper → event-action
агент → озвучка ответа через Fish Audio S2 Pro. Всё локально (LLM и TTS —
внешние эндпоинты, задаются в `.env`).

## Возможности

- Захват микрофона через `parec` (PulseAudio/PipeWire).
- Детекция речи silero-vad на чанках по 32 мс.
- Нарезка сегмента по паузе (`--chunk-silence`) с пред-роллом (`--pre-roll`).
- Транскрипция `large-v3-turbo` на CUDA (или CPU).
- Ограничение языка списком `--languages` с фолбеком при мисдетекте.
- LLM-диалог (OpenAI-совместимый API): мастер-промпт `system_prompt.txt` и
  полная история сообщений, обработка в отдельном потоке.
- Озвучка ответов через Fish Audio S2 Pro (`s2.cpp`): профиль голоса
  `.s2voice`, инлайновые теги, стриминговое воспроизведение.
- Модульная event-action система: модули могут добавлять несколько событий,
  обработчиков и действий без изменения ядра.
- Области модулей: корневые модули доступны main, а `modules/<agent_type>/`
  — только соответствующему типу субагента.
- Мультимодальные события: модель получает только поддерживаемые ею
  `image`, `audio` и `video`.
- Параллельное исполнение действий и встроенные субагенты для создания
  новых модулей.

## Установка

Нужен Python ≥ 3.10. CUDA-библиотеки cuBLAS/cuDNN ставятся из pip-пакетов
`nvidia-*` и не требуют системного CUDA Toolkit.

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[cuda]'   # без GPU: .venv/bin/pip install -e .
```

Захват звука идёт через `parec` из пакета `pulseaudio-utils`:

```bash
sudo pacman -S pulseaudio-utils    # Arch
```

## Запуск

```bash
.venv/bin/jarvis                 # large-v3-turbo на CUDA, языки ru/en
.venv/bin/jarvis --device cpu    # без GPU
.venv/bin/jarvis --language ru   # только русский (жёстко)
```

Эквивалент без установки entry point:

```bash
.venv/bin/python -m jarvis
```

CUDA-каталоги `nvidia/cublas/lib` и `nvidia/cudnn/lib` из venv подставляются в
`LD_LIBRARY_PATH` автоматически (`jarvis/bootstrap.py`); shell-обёртка не
нужна.

## Модели

Модель Whisper скачивается faster-whisper автоматически при первом запуске.

Для предзагрузки в кэш или скачивания через зеркало есть `download_model.sh`:

```bash
./download_model.sh                                # large-v3-turbo
HF_ENDPOINT=https://hf-mirror.com ./download_model.sh
./download_model.sh --tiny                         # маленькая модель для проверки
```

VAD-модель silero скачивается автоматически в `models/silero_vad.onnx`.

## LLM (OpenAI-совместимый API)

Если задан `LLM_MODEL`, каждая расшифровка уходит в OpenAI-совместимый чат.
Ассистент держит контекст
(мастер-промпт + вся история сообщений, без обрезки) и работает в отдельном
потоке: пока он занят, новые реплики накапливаются и отправляются одним
запросом.

```bash
cp .env.example .env       # LLM_API_KEY, LLM_BASE_URL, LLM_MODEL
$EDITOR system_prompt.txt  # мастер-промпт
.venv/bin/jarvis
```

Пути переопределяются флагами `--env-file` и `--system-prompt`; `--no-llm`
выключает LLM. Без `LLM_MODEL` работает только расшифровка.

## Event-action ядро

Каждое событие, поступившее агенту, хранится отдельным сообщением контекста
с ролью `user`. Роль обозначает транспортный формат Chat Completions, а смысл
определяется JSON события:

```json
{"type":"speech","data":{"text":"Посмотри курс биткоина"}}
```

Модель обязана возвращать структурированный объект по строгой JSON Schema:

```json
{
  "actions": [
    {"type":"speech","data":{"text":"Сейчас посмотрю."}},
    {"type":"market.quote","data":{"symbol":"BTC","currency":"USD"}}
  ]
}
```

Действия из одного ответа запускаются параллельно. Каждое завершение
становится отдельным событием `action_result`. Пока агент думает или выполняет
действия, новые события копятся в очереди; при следующем запросе каждое из
них добавляется отдельным сообщением. `no_action` — обязательное одиночное
действие, означающее завершение текущего цикла ожиданием новых событий.

CLI выводит только сообщения, добавляемые в контекст модели: каждое событие и
каждый JSON-ответ модели печатаются отдельной красиво форматированной JSON-
структурой без внутренних дублей. Отдельные сырые STT-строки и префикс
`Jarvis:` при включённом LLM не выводятся. Служебные статусы оборудования
помечены явно: `STT Whisper: ...` и `TTS Fish Audio: ...`.

При переходе VAD из тишины в речь TTS прерывается немедленно, ещё до Whisper.
В этот момент main удерживается занятым до события `speech`: результаты
прерванных действий TTS и все остальные события остаются в очереди, а после
расшифровки поступают одной пачкой в контекст.

## Мультимодальный ввод

При старте Jarvis запрашивает `GET /models` у настроенного OpenRouter и для
выбранной модели читает `input_modalities`. Сейчас поддерживаются `text`,
`image`, `audio` и `video`; тип `file` ядро намеренно не обрабатывает. Файл
должен разобрать сам модуль и передать в событие уже подготовленную
мультимодальную часть с MIME-типом и base64-данными.

В мастер-промпт каждого агента добавляется список доступных модальностей этой
модели. Событие при этом остаётся одним сообщением: его структурированный
JSON-текст идёт первым, затем — поддержанные нативные части.

## Пользовательские модули

Все создаваемые Jarvis модули находятся в `modules/` в корне репозитория.
Каталог целиком игнорируется Git (`.gitignore`) и при создании бинарной версии
будет перенесён в системный каталог конфигурации.

Модуль — комплект обработчиков и действий для агента; он может содержать оба
типа или только один из них. Структура каждого модуля строго такая:

```text
modules/example/
  module.json
  module.py
  actions/
  handlers/
```

`module.py` экспортирует `create_module()`, возвращающий `Module`. Модуль
может объявлять любое количество действий и обработчиков, включая только
обработчики или только действия. Код действий размещается в `actions/`, код
обработчиков — в `handlers/`. Описание Python API находится в
`jarvis/module_api.py`, а встроенный разработчик модулей использует тот же
контракт автоматически.

Области доступа имеют такую структуру:

```text
modules/
  telegram/                  # доступен main
  developer/
    git_tools/               # доступен только типу developer
```

Действие `module.copy` разрешает переносить модули между любыми областями,
включая копирование из области субагента в `main`.

Главный агент получает встроенные действия `module.create`, `module.update`
и `module.delete`. Они запускают разработчика модулей как субагента. Тот
работает в указанной области `modules/<scope>/<name>` (для `main` —
`modules/<name>`), задаёт вопросы родителю через
`agent.message`, пишет код, запускает проверки, вызывает `module.validate`, а
после успешного завершения — `module.complete`. Ядро сразу подключает новый
модуль и обновляет JSON Schema действий. При следующем запуске Jarvis снова
сканирует `modules/` и включает описания найденных возможностей в
контекст.

Типы субагентов можно сохранять действиями `agent.preset_create`,
`agent.preset_delete` и `agent.preset_list`. Их данные находятся в
`.jarvis/agents/presets.json`, который также относится к runtime-состоянию и
не попадает в Git.

## TTS (Fish Audio S2 Pro)

Ответ LLM озвучивается через [s2.cpp](https://github.com/rodrigomatta/s2.cpp)
(`q4_k_m`, CUDA). Jarvis сам поднимает сервер при старте, если он не запущен, и
останавливает его при выходе — модель в VRAM только пока работает Jarvis.
Внешний сервер (запущенный вручную) Jarvis не трогает.

Референсный голос уже в репозитории: `assets/voices/jarvis_reference.mp3` и
`assets/voices/jarvis_reference.txt`. При первом запуске профиль
`assets/voices/jarvis.s2voice` создастся автоматически.

Настройки TTS в `.env` (шаблон — `.env.example`): `TTS_URL`, `TTS_VOICE`,
`TTS_VOICE_DIR`, `TTS_AUTOSTART`, `TTS_SERVER_BIN`, `TTS_MODEL`,
`TTS_TOKENIZER`, `TTS_SERVER_ARGS`, `TTS_REFERENCE`, `TTS_REFERENCE_TEXT`.

Синтез идёт стримом PCM в `ffplay` (нужен пакет `ffmpeg`). Пока реплика
воспроизводится, main-агент считается занятым и не делает новый запрос к LLM.
При новом STT-событии текущая реплика и вся очередь TTS сбрасываются; каждая
отменённая реплика возвращает свой `action_result` с ошибкой `interrupted`.
Речь управляется инлайновыми тегами в квадратных скобках (`[whisper]`,
`[excited]`, `[sigh]` и т.п.) — их расставляет LLM согласно мастер-промпту;
набор тегов свободный и не ограничен. `--no-tts` отключает озвучку.

## Параметры

| Флаг | По умолчанию | Назначение |
| :--- | :--- | :--- |
| `--model` | `large-v3-turbo` | Модель faster-whisper |
| `--device` | `cuda` | Без фолбека: при отсутствии CUDA — ошибка с подсказкой |
| `--compute-type` | — | Точность вычислений; по умолчанию `float16` на CUDA |
| `--language` | — | Жёстко заданный язык, напр. `ru` |
| `--languages` | `ru,en` | Допустимые языки; мисдетект → первый из списка |
| `--pre-roll` | `0.5` | Запас аудио перед стартом речи, с |
| `--chunk-silence` | `2.0` | Сколько секунд VAD=false, чтобы завершить запись, с |
| `--threshold` | `0.5` | Порог VAD |
| `--sample-rate` | `16000` | Частота дискретизации |
| `--out-dir` | `segments` | Каталог WAV-чанков |
| `--keep-audio` | — | Не удалять WAV после расшифровки |
| `--input-device` | — | Имя источника PulseAudio |
| `--list-devices` | — | Список источников PulseAudio и выход |
| `--env-file` | `.env` | Файл с параметрами LLM и TTS |
| `--system-prompt` | `system_prompt.txt` | Файл мастер-промпта |
| `--no-llm` | — | Только расшифровка, без LLM |
| `--no-tts` | — | Не озвучивать ответы |
